## Context

0032 sent the composed stack's pages with no Content-Security-Policy, and
said why: "React and Angular add inline styles at run time, and a policy
no gate has seen working in a browser would be a claim nobody checked."
Since then 0069 put the examples page under a policy that refuses anything
inline, and its gate showed both renderers working under it: React and
Angular set a style through the CSSOM, which `style-src` does not govern,
as that record says.
0070 put the live demo, the host page's demo build, under the same policy
with `'unsafe-inline'` in `style-src`, for the style elements AG Grid
Community creates to apply its theme, and showed in Chromium that the
grid's elements are refused without it. 0072 left every page asking no
other host for anything. So the first half of 0032's reason was no longer
true, and the second was the work.

What each page needs was measured, not read. Served by its gate under
0069's policy, on 2026-10-17, on Windows 11:

- **The studio** refused nothing in Chromium 153.0.8010.12 or Firefox
  155.0, at any step of its journey, its states under review, its version
  download (0062) included, over all 1,212 checks of each browser's run.
  Nothing it does needs a source beyond 0069's.
- **The host page** had style elements refused in both browsers, and
  nothing else: `style-src-elem refused inline`, every report from the
  chunk that holds AG Grid, and Chromium's console naming 18 elements by
  their hashes in the states its first pass reached. Without them the grid
  drew unstyled, 890 pixels wide at a 320-pixel window, and its paging
  panel took a click meant for the page, so the journey stopped in its
  first pass in each browser; every state it reached after the grid was
  drawn heard nothing more refused, and no style attribute was refused in
  any of them.

The host page's built bundle holds no `eval` and no `new Function`; it
holds one call of the global `Function`, AG Grid's evaluator of column
expressions given as strings, which the page gives none of. Angular's
components are compiled ahead of time (`ɵcmp` in the bundle, no compiler).

## Decision

**The studio and the host page are each sent, with every file under them,
the examples page's Content-Security-Policy (0069) with only the sources
each was measured needing, each named with why: none for the studio, and
`'unsafe-inline'` in `style-src` for the host page, as the live demo's
(0070). The policies are defined in `scripts/web-policies.mjs`;
`deploy/web/nginx.conf` sends them from a map that module writes; the
studio's and the host page's browser gates serve each page under its
policy and fail, in every browser, on anything the browser refuses under
it.**

- **The studio:** `default-src 'none'; script-src 'self'; style-src 'self';
  font-src 'self'; img-src data:; connect-src 'self'; object-src 'none';
  base-uri 'none'; form-action 'none'; frame-ancestors 'none'`.
- **The host page:** the same with `style-src 'self' 'unsafe-inline'`.
- **Each directive, for both.** Scripts from the page's origin alone, and
  nothing inline or evaluated. Styles and fonts from it alone, where the
  build's stylesheet and faces are (0072). `data:` images, because
  `index.html`'s icon is `data:,` and the Blueprint theme draws its date
  and time icons as `data:` SVGs, and no image from anywhere else, the
  origin included: the pages load none. Fetches to the origin alone, which
  is where `/v1` is (0024, 0029). No plugin, no `<base>`, no form sent
  anywhere by the browser -- the pages send what a form holds through
  their client, and nothing was refused under `form-action 'none'` --
  and no framing, as `X-Frame-Options: DENY` already says. Anything a
  directive does not name -- a frame, a worker, media, a manifest -- the
  pages have none of.
- **`'self'` is the composed stack's origin**, `/v1` and the other page
  included, not the page's path: a source with a path would hold each
  page to its own files, but the gates serve the builds at `/`, where such
  a policy could not be measured -- 0069's reason.
- **Sent by nginx from one map.** `map $uri $formancy_content_security_policy`
  gives each page's location and everything under it its policy and every
  other path nothing, and one `add_header Content-Security-Policy
  $formancy_content_security_policy always;` sends it, beside the server's
  other headers, so no location needs an `add_header` of its own -- which
  in nginx would drop the server's -- and a 404 under a page carries it
  too. An empty value is not sent, so `/v1/`, `/health`, the redirects and
  nginx's own 404 carry none. The map is generated:
  `node scripts/web-policies.mjs --write` rewrites it, and the guard fails
  until it is.
- **The runtime door's server, 8081, sends none:** it serves no file
  (0037), and the guard holds every location of either server to a page's
  files, the data server, a redirect or an error.
- **Nothing moves a request out of its page.** nginx chooses the header's
  value by the path an answer is sent for, so an `error_page`,
  `try_files`, `rewrite` or `index` that sent a request under a page to a
  path outside it would send that answer with another value or none; the
  guard refuses one.

## Consequences

**What it buys.** No script element runs in the studio or the host page
but one served from the stack's origin: one written into a page inline,
whether by a flaw in the page, a proxy or an extension, is refused, and
so is a load from any other host, a form sent elsewhere, and the pages
framed. The studio holds an administrator's token, which publishes forms
(0024); the host page a host's, which writes records
(0029): both are in memory, and in memory is where an injected script
would read them. And the claim is the gates', in every browser: the policy
the web image sends is the one every state of both journeys ran under.

**What it costs.**

- **An extension or a page wrapper that writes a script element into the
  page is refused.** An
  extension that puts a script element into the page, a proxy that adds
  an inline script on its way through -- Cloudflare's bot detection, as
  0069 read on formancy.ai -- or a host application that wraps the host
  page and adds one, does not run, and the browser's console says so. A
  feature that serves its script from the page's own hostname, as some of
  Cloudflare's do under `/cdn-cgi/`, is allowed by `'self'`; nothing has
  measured either behind the tunnel (`docs/deploy/cloudflare.md`).
- **A dependency that needs `eval` or an inline script, or in the studio
  an inline style, fails the gates.** AG Grid's string expressions,
  Angular's JIT compiler, a library that injects a style element into the
  studio:
  each is refused, and each gate fails on the first state it reaches,
  before anybody ships it. That is the point, and it is also a
  dependency upgrade that stops at the gate.
- **The host page allows inline styles.** A style injected into it can
  restyle the page -- cover a button, hide a notice -- though `img-src`,
  `font-src` and `connect-src` keep it from loading anything from another
  host. AG Grid's style elements are why; the gate's check that they
  are refused without it is what keeps the allowance from outliving them.
- **`'self'` is the whole origin.** On the composed stack that is the two
  pages and `/v1`; a deployment whose proxy serves other files on the same
  origin lets the pages load scripts from them.
- **A deployment's own proxy copies it, or there is none.** nginx.conf is
  the shape a deployment's proxy copies (0032); one that does not send the
  header serves the pages with no policy, and nothing here reads what a
  deployment sends. A host page moved to an origin of its own, as 0060
  allows, needs a `connect-src` that names the server's origin: this
  policy refuses that call, and no gate runs it.
- **Nobody hears a refusal in a visitor's browser.** There is no
  `report-to`: the console is the only place it is said.
- **The gates now load axe outside the page's policy**, through
  Playwright's evaluate, which the policy does not hold, as 0069
  measured in Chromium and Firefox and the two gates' axe checks ran so
  in all three browsers: a script element would have been refused. What
  the gates check of the page is the page's.
- **WebKit was measured once, off CI.** Both gates passed in Playwright's
  WebKit 26.6 inside Playwright's own Linux image,
  `mcr.microsoft.com/playwright:v1.63.0-noble`, on 2026-10-17 -- the
  studio's 1,212 checks and the host page's 2,249, its allowance's
  included, so WebKit too refuses AG Grid's style elements under 0069's
  policy -- and no browser refused anything another did not, so no row
  of 0058's `FACTS` names a difference. From here on only CI's WebKit
  leg holds it, since WebKit runs on Linux alone.

**What it does not do.** No hold on a script the browser runs in the page
itself rather than as one of the page's elements: Playwright's evaluate and
init scripts, through which the gates run axe and their listener, run
unrefused, and what an extension runs as its own was not measured. No
policy for the server's own answers, which are JSON and never a document;
no `Permissions-Policy` on the composed stack, where 0069's examples page
sends one; no reporting endpoint; nothing that
reads what a deployment's proxy sends.

**What it forecloses.** Nothing that cannot be undone: the map is one line
a page.

## Alternatives considered

**None, as 0032 said.** Its reason was that React and Angular add inline
styles at run time and that nothing had seen a policy working. Measured,
neither page had a style attribute refused under 0069's policy, and only
AG Grid's style elements need an allowance; and the gates now see the
policies working in every browser they run.

**`Content-Security-Policy-Report-Only` first.** It refuses nothing, and
with nowhere to send reports it is a console line nobody reads. The gates
are where a refusal is heard, and they hear none.

**One policy for both pages.** The host page's, `'unsafe-inline'` and all,
would loosen the studio -- the page that holds the administrator's token --
for a need only the host page has. The map costs a line a page.

**Hashes or a nonce for AG Grid's style elements.** Hashes would have to
be read from a browser, 18 of them in one pass of Chromium's, and change with every grid upgrade
and theme parameter. A nonce needs a fresh value in every page's
response and header -- nginx can write one with `sub_filter` and
`$request_id` -- and the page to hand it to every grid as `styleNonce`;
the live demo's static assets cannot (0070), and a deployment's proxy
would need the same machinery. It is one way to drop the allowance, and
not taken yet; AG Grid's legacy stylesheets, below, are another.

**AG Grid's legacy themes, served as a stylesheet.** AG Grid 36.2.0 still
ships its v32 themes as CSS files (`ag-grid-community/styles/ag-grid.css`,
`ag-theme-quartz.css` and the others), and a grid given `theme: 'legacy'`
creates no style element: in `ag-stack` 36.2.0's
`dist/package/main.esm.mjs`, read on 2026-10-17, `handleThemeChange`
injects the core and module CSS only for a theme object, and
`addGlobalCSS` only queues CSS while there is none. Served from `'self'`
like the build's own stylesheet, they would let the host page's
`style-src` drop `'unsafe-inline'`. But they are the styling AG Grid's
Theming API replaced as the default in v33, as its own console warning
says, and the host page's grid is the Quartz theme recoloured through its
parameters, each a variable of the room's or a mix AG Grid computes, which
`apps/host/src/grid-theme.test.ts` holds: under the legacy themes those
would become CSS of the page's own, which nothing holds yet. Not measured:
whether the host page passes its gate under `style-src 'self'` with them.

**`'unsafe-inline'` in `style-src-elem` alone, refusing style
attributes.** Measured, the host page needs no style attribute. But an
injected style attribute can do nothing an injected style element cannot,
and a browser without `style-src-elem` -- Firefox before 108, Safari
before 15.4 -- would fall back to `style-src 'self'` and refuse AG Grid's
elements.

**A `<meta>` policy in each `index.html`.** It would travel with the build
to any proxy. But a meta policy cannot carry `frame-ancestors`, and a
browser enforces both a meta policy and a header: an operator who needs
another `connect-src` for a host page on an origin of its own (0060)
could not loosen what the build carries, whatever the proxy sends.

**The live demo's policy module for the host page.** `LIVE_POLICY` is the
same text today, but it is the policy of a page on formancy.ai under
Cloudflare's static assets (0070), and the composed stack's is the web
image's. Two modules that build both from 0069's with one named allowance
each can drift apart only by an edit to one of them, which its own test
names.
